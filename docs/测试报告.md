## 四、测试过程中发现并修复的缺陷

### 缺陷 1：CLI 在非 UTF-8 控制台崩溃（已修复）

- 发现方式：M13 调用冻结 `ZBridge.exe --verify-all` 时捕获到异常。
- 现象：`UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'`，进程崩溃、无输出退出。
- 影响范围：**严重**。中文 Windows 控制台默认 GBK，`--verify-all` / `--selftest` / `--report` 三个 CLI 入口全部会崩；GUI 不受影响（Tk 可渲染 unicode），但命令行模式完全不可用。
- 根因：报告文案使用了 GBK 无法编码的字符 `✓`(U+2713)、`→`(U+2192)、全角 `（）＜`。
- 修复：
  1. `max_span_report()` 与 `verify_all_jumps()` 中相关符号改为 ASCII（`->`、`[OK]`、`()`）；
  2. `main()` 的 CLI 分支增加 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` 兜底；
  3. `--verify-all` 结束显式 `sys.exit(0)`。
- 复验：重建 exe 后 `ZBridge.exe --verify-all` 退出码 0、输出 26KB 完整矩阵、含正确汇总行；`ZBridge.exe --selftest` 退出码 0。
