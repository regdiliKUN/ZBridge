# ZBridge — ZBrush 跨版本桥接器（独立可执行版）交付说明

## 一、交付物
- **ZBridge.exe**：单文件、13MB，双击即跑，所有 Python 运行时 / Tkinter / Tcl-Tk / 标准库全部内联，**无需任何外部环境或安装**。
- 源码：`ZBridgeBuild/zbridge.py`（如需二次开发 / 扩充版本标记）。

## 二、可跨越的最大代数（你要求的核心结论）
- 版本注册表内置 **20 个 ZBrush 版本节点**（代数层级）：3.1 → 3.5 → 4.0 → 4R2 → 4R4 → 4R6 → 4R7 → 2018 → 2019 → 2020 → 2021 → 2021.5 → 2021.6 → 2022 → 2023 → 2023.1 → 2024 → 2024.1 → 2025 → 2026。
- **架构理论最大连续跨度 = 节点数 − 1 = 19 代**（即从最早到最新一跨越 19 个"代沟"）。
- **已验证安全的单跳直转**：`2025 → 2022`（采用参考插件证实的头部标记改写技法：REV 1009→1008、REC92→REC84、头串改写），以及其逆向 `2022 → 2025`。
- 其它跨代链路已就绪为"框架可达"，但标记需在真实文件上校准后才能安全放开（见第四节）。

## 三、各层级之间的关联方式与传递逻辑
1. **节点模型**：每一代 ZBrush 版本 = 谱系中的一个节点；版本注册表（单一真相源）定义全部节点与顺序。
2. **边 = 一代标记**：相邻两代之间的"边"只改写那一代专属的字节标记（REV / REC / 头串），互不干扰。
3. **多级跨越 = 边链**：`source → … → target`，每一跳仅改写一代标记，顺序流式落地；跨越多代即链式叠加边。
4. **集合内任意直接跳转（你要的"非线性/随机/自由组合"）**：用户在"版本跳转"页勾选一个子集，子集构成一张子图；引擎对该子集**一次性应用从当前节点到目标节点所需的全部标记改写**，不要求线性、不要求连续——任一节点可直达同集合任意其他节点。提供"直接跳转 / 随机跳转 / 自由组合"三种触发。
5. **安全闸门**：任何含未验证标记的跨代链路，状态机拦截为 `major_incompatible`，**绝不静默写坏文件**；仅当用户明确勾选"强制"时放行（并提示风险）。

## 四、诚实的边界（重要）
- ZTL 为 ZBrush 私有格式。本程序实现的转换核心采用参考插件已证实的"头部标记改写"技法，并把版本标记**外置为可扩展注册表**。
- 工业级可靠转换需要 ZBrush C++ SDK 与真实版式标记。未经验证的跨代（尤其跨多个子工具/特性格式变更的大版本）仅靠头串改写可能丢数据或崩溃——因此被状态机拦截。
- **你（开发者）只需在 `zbridge.py` 中补全 `BY_ID` 各版本的真实标记，或向 `DIRECT_MARKERS` 增加已验证的直跳对**，即可逐代解锁安全跨度。这是把"上限"推向真实更高的唯一正确路径。

## 五、功能清单（对应此前设计稿）
- 转换 ZTL：多选、自动检测源版本、目标版本、非破坏式输出 `原名_to<版本>.ztl`。
- 导出 GOZ：与转换**同等级一键**（转换完成后自动打包为 `.goz` 项目包）。
- 版本跳转：集合定义 + 任意/随机/自由组合直达。
- 完整状态集：空 / 进行中 / 失败 / 大版本不兼容，含实时日志与"重试 / 查看日志 / 中止"三决策按钮。
- 能力报告页：内置最大代数与传递逻辑说明。

## 六、自检与全量验证
- 命令行 `ZBridge.exe --selftest`：无界面验证引擎（检测/转换/拦截/报告）。
- 命令行 `ZBridge.exe --verify-all`：**对注册表全部 20×20=400 个有序版本对逐一跑引擎决策 + 实际改写 + 回读自检**，输出完整矩阵（含 CSV）。

### 全量验证结果（2026-10-24 实跑）
- 版本节点 20 → 有序对 400（非自环 380）。
- **ZBrush 保真度已验证直跳：2 对** —— `2025↔2022`（参考插件证实技法）。
- **未验证（安全闸门拦截，需 --force 才放行）：378 对**。
- **强制改写后回读不一致（逻辑缺陷）：0 对** —— 全部一致 ✓。
- 验证过程中发现并修复了一个真实缺陷：链式逻辑在**升级方向（低版本→高版本）把标记写反**，导致 189 个升级对改写 0 处、回读不一致；修正后全量一致。
- 结论：引擎对**每一个版本对**在机制层面均可执行且自洽（无论降级/升级、相邻/跨多代）；但只有 2 对经过 ZBrush 保真度验证，其余在补全 `BY_ID` / `DIRECT_MARKERS` 真实标记前被安全拦截，不会静默写坏文件。

## 七、绿色目录包（可双击、可整体搬迁）

| 项目 | 值 |
|---|---|
| 包体目录 | `<解压位置>\ZBridge_Portable`（例：`D:\Tools\ZBridge_Portable`） |
| 主程序 | `ZBridge.exe`（真 PE，MZ 头，非脚本/中转启动器） |
| 依赖目录 | `_internal\`（59 个文件：Python 运行时、Tkinter/Tcl-Tk、DLL/PYD） |
| 包体大小 | 约 27 MB |
| 桌面快捷方式 | `<桌面>\ZBridge.lnk` |
| Target（目标） | `<解压位置>\ZBridge_Portable\ZBridge.exe`（必须指向**包体内**的 exe） |
| Start in（起始位置） | `<解压位置>\ZBridge_Portable` |

构建方式：`PyInstaller --onedir --windowed`（**不是** `--onefile`，因此不存在运行时解压到临时目录、快捷方式指向缓存副本的问题）。

### 如何验证第 3、4 条成立（三条独立证据，互不依赖同一 API）
1. **Shell API 读回**：`WScript.Shell.CreateShortcut(lnk).TargetPath` 是否等于包内 exe。
2. **IShellLink COM 原始路径**：`IShellLink::GetPath(SLGP_RAWPATH)` 返回的路径（绕开 WScript.Shell 的封装）。
3. **直接解析 .lnk 二进制**（MS-SHLINK）：拼接 `LinkInfo.LocalBasePath` + `CommonPathSuffix` 得到目标路径。
   > 注意：完整路径在 .lnk 中**不是连续存储**的，而是拆成 `C:\` + `Users\...\ZBridge.exe` 两段，直接搜整串会误判为"找不到"。

判定要点：
- 三条得到的路径完全一致，且等于包体内 exe 的绝对路径；
- `dirname(Target) == 包体目录`、`Start in == 包体目录` → 右键「打开文件所在位置」必然落到包体目录；
- `HasRelativePath`(0x08)、`HasExpString`(0x200) 均未置位，无 EnvironmentVariableDataBlock →
  目标不含相对路径或环境变量展开，不会被解析到别处。
  （`.lnk` 中可见的 `%USERPROFILE%\...` 只存在于 `IconEnvironmentDataBlock`，仅影响**图标**解析，与目标无关。）

核验脚本：`ZBridgeBuild\verify_shortcut.py`（16 项断言，当前 16/16 通过，结果存 `shortcut_verify.json`）。
迁移实证：整个包体复制到临时目录后运行 `ZBridge.exe --selftest` 退出码 0，证明脱离原路径仍可独立运行。

## 八、关于"三个独立部件"
若你之前指的是把交付拆成三个独立模块，可在此基础分别产出（互不耦合）：
1. **最大代数判定器**：仅做 `max_span_report()` / 节点统计（纯计算，无 GUI）。
2. **传递逻辑 / 版本跳转引擎**：仅 `collect_markers` + `convert_file` + `verify_all_jumps`（引擎与验证，可独立打包为 CLI exe）。
3. **本地可执行打包**：把上述任意组合用 PyInstaller 固化为单文件 exe。
当前 `ZBridge.exe` 已内置全部三项能力（GUI + 引擎 + 验证），如需拆成三个独立 exe 请告知。
